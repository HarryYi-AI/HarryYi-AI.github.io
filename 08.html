Quant 面试复习手册 08｜防泄漏工程（完整讲解版）：Purged Walk-Forward 代码精读

📌 Quant 面试复习手册 · 第 8 篇（补充篇）
本篇是第 1 篇（多重比较/样本内外纪律）与第 4 篇（机器学习）的工程落地：用真实的两个切分函数，讲透时序回测里最核心的防泄露机制——Purge（挖标签泄露）+ Embargo（堵自相关传染）+ 三层验证隔离。
参考：López de Prado《Advances in Financial Machine Learning》第 7 章（Purged K-Fold & Embargo）。

1. 为什么时序回测必须"挖洞"：三条泄露通道

普通 K-Fold 交叉验证在时序数据上是错的，因为它随机打乱时间。量化回测有三条独特的泄露通道：

泄露通道 出问题的场景 堵法
① 标签泄露（Purge） 训练集最后几天的样本，标签 Y 用到了测试期内的价格 挖掉 horizon 天
② 自相关传染（Embargo） 相邻两天特征高度重叠（60 日滚动窗口），训练窗尾部信息渗进测试期 再挖 embargo 天
③ 超参过拟合 调参时偷看了外层测试集 三层隔离：inner_train / inner_val / 外层 test

具体到标签定义：t 日收盘拿到数据算信号 → t+1 日收盘才能建仓（1 天执行延迟）→ 持有 h 天。所以 t 日样本的标签 Y 用到了 t+1+h 天的价格。如果训练集保留到测试期前一天，那几个样本的标签窗口直接跨进测试期——模型等于提前看到了答案。

2. walk_forward_splits 逐行精读

def walk_forward_splits(dates, first_test_year=2018, last_test_year=2025,
                        horizon=5, embargo=5, holdout_start="2025-11-10"):
    if not dates.is_monotonic_increasing:
        raise ValueError("dates must be sorted in ascending order")
    elig_dates = dates[dates < pd.Timestamp(holdout_start)] if holdout_start is not None else dates
    for year in range(first_test_year, last_test_year + 1):
        test = elig_dates[elig_dates.year == year]
        if len(test) == 0:
            continue
        start = int(elig_dates.get_loc(test[0]))
        cutoff = max(start - horizon - embargo, 0)
        train = elig_dates[:cutoff]
        if len(train) == 0:
            continue
        yield train, test

2.1 逐行拆解

① 参数即设计决策：

  • horizon=5：标签周期（预测未来 5 天收益）——它同时决定 purge 的宽度。标签定义"t 日信号 → t+1 收盘建仓 → 持有 h 天"意味着 t 日样本的标签用到 t+1+h 的价格
  • embargo=5：额外的隔离带。特征是 60 日滚动窗口算的，相邻两天特征高度自相关——purge 堵住标签泄露的"明道"，embargo 再堵自相关传染的"暗道"。合计挖掉 horizon+embargo = 10 个交易日
  • holdout_start="2025-11-10"：之后的日期被永久挖出池子，只留给最终 12 个月留出集——测试集只碰一次纪律的代码化

② 逐年滚动（生成器 yield）：for year in range(2018, 2026)——2018 做测试、之前年份做训练；下一轮 2019 做测试、训练集扩大……Walk-Forward 的标准形态。用生成器逐年按需产出，内存友好且天然表达"滚动"语义。

③ 定位用行号，裁剪按行数：

start = int(elig_dates.get_loc(test[0]))       # 第一个测试日的行位置
cutoff = max(start - horizon - embargo, 0)     # 往回数 10 行
train = elig_dates[:cutoff]

get_loc 返回位置索引。裁剪 [:cutoff] 按行数（矩阵行）走，不是按日历日期——如果测试年第一个月有停牌空洞，按日期减天数会少挖。精确挖掉 10 行交易日是这段代码的硬承诺。

④ 被挖掉的 10 天两边都不属于——既不在训练集也不在测试集，直接丢弃。这正是"Purge"的字面意思。

2.2 图示（2019 测试年为例）

时间轴： 2010 ────────────────────── 2018 ──────│ purged 10 天 │────── 2019 ──→
         └──────── train（训练集）──────┘              └──── test（2019 全年）────┘
                                          ↑
                              horizon(5) + embargo(5) = 10 个交易日，两边都不要

3. split_train_inner_val：超参数的"受操控试错场"

def split_train_inner_val(train_dates, val_days=242, horizon=5, embargo=5):
    if len(train_dates) <= val_days + horizon + embargo + 60:
        val_days = max(60, len(train_dates) // 5)
    val_start = len(train_dates) - val_days
    inner_val = train_dates[val_start:]
    inner_train_end = max(val_start - horizon - embargo, 0)
    inner_train = train_dates[:inner_train_end]
    return inner_train, inner_val

3.1 它解决什么问题

超参数（Ridge 的 α、LightGBM 的叶子数、早停轮数）必须找一个"试错场"，但这个场绝不能是外层 walk-forward 的 test 年——在测试集上调参 = 多重比较过拟合（第 1 篇）。解法：从训练窗内部再切一块时间上最靠后的子集做内验证。

3.2 三个设计要点

  1. 内验证 = 时间窗最后一段，且严格时序——绝不能随机 K-Fold：随机打乱时序做交叉验证，训练集混入测试期邻域样本，交叉验证分数虚高。时序 ML 第一诫：验证集永远取时间上最后的一段
  2. 同样的 purge + embargo：inner_train_end = val_start − 10——内训练窗与内验证窗之间挖掉同样的 10 天，泄露机制完全相同，防法也相同
  3. 最小长度保护：训练窗 ≤ 242+10+60 行时，固定 1 年验证集会把训练挤空；退化规则 val_days = max(60, len//5)，且 +60 保证内训练至少剩 60 行

3.3 三层隔离结构（整个项目防过拟合的骨架）

层 用途 访问规则
inner_train 拟合模型参数 随便碰
inner_val 选超参数（α、num_leaves、早停轮数） 只在训练窗内部，时间上最靠后
walk-forward test（逐年） 报告最终性能 每年一次，调参信息绝不回流

为何内验证取"时间上最后一段"：它最接近真实使用场景（用过去预测未来），且与外层测试年的分布漂移程度最相似——用最近的过去选超参，泛化到最近的将来最稳。

4. 与全项目的咬合关系

上游设计决策 在这段代码里的体现
"5d/20d 是标签周期先验，不是网格搜索的超参" horizon 是函数入参（5），它同时决定 purge 宽度；换成 20d 标签时 purge 自动变 25 天，不用改代码
"20d 窗口重叠 → 有效样本少 → Newey-West" 标签跨期重叠正是 purge 要处理的问题的另一面：评估端用 NW 修 t 值，切分端用 purge 防泄露
"留出集只跑一次" holdout_start 在最外层挖掉，inner/walk-forward 全都碰不到
"调参绝不偷看测试集" 超参选择被强制圈死在 inner_val
"多日窗口重叠 → 自相关" embargo 的存在理由：60 日滚动窗口特征相邻日高度重叠

5. 面试追问预演

Q1：为什么不用随机 K-Fold？
时序样本相邻高度自相关，随机打乱后训练集混入测试期邻域样本，交叉验证分数虚高。正确做法：时序切分 + purge/embargo。

Q2：embargo 为什么是 5，不是 60？
权衡问题：embargo 每多一天，训练集就少一天（偏差增加），换取泄露风险下降。5 ≈ 标签周期同量级；严格讲可以设为"特征最长窗口的自相关衰减长度"（本项目 60 日窗口可讨论更长），但样本代价必须评估。

Q3：horizon 改成 20，代码要改吗？
不用改代码——purge 自动变 20+5=25 天（入参驱动）。但每个测试年要多挖 15 天训练样本，早期年份可能触发 continue 跳过。

Q4：get_loc 按行裁剪和按日期裁剪有区别吗？
有。若测试年第一个月有停牌空洞，按日历日期减 10 天会少挖行（空洞日不占行）；按行数裁剪保证精确挖掉 10 行交易日。停牌频繁的 A 股数据里这个区别是实质性的。

Q5：为什么用生成器 yield 而不是返回列表？
逐年按需产出，内存友好，且天然表达"滚动扩大训练集"的语义；调用方训练完一年再要下一年。

6. 自测清单（必须掌握的考点）

  • ☐ 三条泄露通道（标签泄露/自相关传染/超参过拟合）与三个堵法（purge/embargo/三层隔离）一一对应
  • ☐ purge 宽度 = horizon + embargo；horizon 改 20 时 purge 自动变 25
  • ☐ 裁剪按行数不按日历日期；停牌空洞下的差异
  • ☐ 内验证必须取时间最后一段；随机 K-Fold 为什么错
  • ☐ 三层隔离：inner_train / inner_val / walk-forward test 各自的访问规则
  • ☐ 最小长度保护逻辑（val_days 退化规则）
  • ☐ embargo 的权衡本质：样本变少（偏差）vs 泄露风险下降

7. 30 秒速查总表

考点 一句话
Purge 挖 horizon 天：堵标签跨期泄露
Embargo 再挖隔离带：堵特征自相关传染
裁剪方式 按行数（交易日），不按日历日期
切分纪律 时序顺序切分；内验证 = 时间最后一段
三层隔离 inner_train 拟合 / inner_val 选超参 / 外层 test 只报告
horizon 变更 入参驱动，purge 自动 = horizon + embargo
随机 K-Fold 时序数据禁用（自相关泄露）
